# Ресторан «Лотос» — веб-приложение

Полноценное учебное веб-приложение для ресторана японской кухни «Лотос»: меню, бронирование столов, оформление заказов и разграничение доступа по ролям.

Предметная область и структура базы данных восстановлены по лабораторным работам из папки [`lab`](lab): категории, блюда, сотрудники, столы, заказы, состав заказа, поставки, бронирования.

## Стек

- **Backend:** Node.js, Express, TypeScript, `pg`, `express-session`.
- **Database:** PostgreSQL, расширение `pgcrypto` для хеширования паролей.
- **Frontend:** HTML, CSS, TypeScript, компилируемый в `public/js`.
- **Авторизация:** cookie-сессия, роли `admin`, `waiter` и `guest`.

## Быстрый старт

### 1. Требования

- Node.js 18 или новее.
- PostgreSQL 14 или новее (проект проверялся на PostgreSQL 18).
- Запущенная служба PostgreSQL.

`psql` в `PATH` не обязателен: инициализация базы выполняется Node.js-скриптом через библиотеку `pg`.

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка окружения

Скопируйте пример в `.env`:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите реальные параметры подключения, прежде всего пароль пользователя PostgreSQL:

```env
PORT=3000
DB_HOST=localhost
DB_PORT=5432
DB_NAME=iris_restaurant
DB_USER=postgres
DB_PASSWORD=ваш_пароль
SESSION_SECRET=случайная_строка
```

### 4. Инициализация базы данных

```bash
npm run db:init
```

Скрипт [`src/scripts/init-db.ts`](src/scripts/init-db.ts):

1. Подключается к служебной базе `postgres`.
2. Проверяет, существует ли база `iris_restaurant`.
3. Если базы нет — создаёт её командой `CREATE DATABASE`.
4. Применяет [`db/schema.sql`](db/schema.sql).
5. Загружает тестовые данные из [`db/seed.sql`](db/seed.sql).
6. Создаёт функции и триггеры из [`db/triggers.sql`](db/triggers.sql).

**Создавать базу через `createdb` вручную не нужно.** Это делает `npm run db:init`. Если база уже существует, скрипт не удалит её, а пересоздаст таблицы и заново загрузит тестовые данные.

### 5. Сборка фронтенда

```bash
npm run build:client
```

Или полная сборка сервера и клиента:

```bash
npm run build
```

### 6. Запуск

```bash
npm run dev
```

Откройте в браузере: [http://localhost:3000/login.html](http://localhost:3000/login.html)

Для запуска собранной версии:

```bash
npm run build
npm start
```

## Демо-доступ

| Роль | Логин | Пароль | Возможности |
|---|---|---|---|
| Администратор | `admin` | `admin123` | панель управления: заказы (просмотр и смена статуса), брони, сотрудники, столы, поставки, аналитика |
| Официант | `waiter` | `waiter123` | общая учётка официантов: выбор стола и официанта, каталог блюд, корзина, создание заказов |
| Гость | `guest` | `guest123` | меню, поиск, бронирование стола |

Учётная запись `waiter` не привязана к конкретному сотруднику (`employee_id = NULL`). Кто именно обслуживал стол, официант выбирает в выпадающем списке при оформлении заказа.

### Жизненный цикл заказа

```text
новый -> готовится -> подан -> оплачен -> закрыт
   \         \          \
    -> отменён <- отменён <- отменён
```

Закрыть заказ без оплаты нельзя: переход `подан -> закрыт` отсутствует.

## Схема базы данных

Основные таблицы:

- `categories` — категории меню;
- `dishes` — блюда;
- `employees` — сотрудники;
- `restaurant_tables` — столы;
- `orders` — заказы;
- `order_items` — состав заказа;
- `supplies` — поставки;
- `bookings` — бронирования;
- `users` — учётные записи и роли.

Связи:

- `categories 1:M dishes`;
- `employees 1:M orders`;
- `restaurant_tables 1:M orders`;
- `orders 1:M order_items`;
- `dishes 1:M order_items`;
- `restaurant_tables 1:M bookings`;
- `employees 1:M supplies`;
- `employees 1:0..1 users`.

Ограничения:

- первичные и внешние ключи;
- `CHECK` на положительные цены, вес, вместимость и количество;
- допустимые статусы заказов, броней, столов и должностей;
- уникальность номера стола и номера накладной;
- частичный уникальный индекс, запрещающий две активные брони одного стола на одно время;
- `ON DELETE CASCADE` для состава заказа и `ON DELETE RESTRICT` для блюд, сотрудников и столов.

## Триггеры базы данных

Файл [`db/triggers.sql`](db/triggers.sql) содержит только три триггера:

| Триггер | Таблица | Событие | Действие |
|---|---|---|---|
| `trg_order_items_recalc_total` | `order_items` | `INSERT`, `UPDATE`, `DELETE` | пересчитывает `orders.total` как `SUM(quantity * unit_price)` по позициям заказа |
| `trg_orders_release_table` | `orders` | `UPDATE OF status` | при переходе в «оплачен» или «закрыт» освобождает стол, если на нём нет активного заказа и брони на сегодня |
| `trg_bookings_reserve_table` | `bookings` | `INSERT` | бронь на сегодня переводит свободный стол в «забронирован» |

Логика переноса брони на другой стол и изменения `table_id` удалена: в веб-приложении такая операция не используется. Отмена и выполнение брони обрабатываются на стороне API через [`src/services/tableStatus.ts`](src/services/tableStatus.ts).

Сумма заказа пересчитывается как `SUM`, а не приращением `total = total + quantity * unit_price`. Для обычной вставки результат тот же, но пересчёт не удваивает сумму, если заказ уже создан с рассчитанным `total` (так делает сервер), и корректно обрабатывает изменение количества и удаление позиций.

## Аналитика

Файл [`db/analytics.sql`](db/analytics.sql) содержит 10 запросов из лабораторной работы. Они доступны через API `/api/analytics/...` и через вкладку «Аналитика» в панели управления. Для гостя запрос свободных столов доступен по публичному маршруту `/api/analytics/free-tables`; раздел бронирования на странице меню использует аналогичный расчёт через `/api/tables/free`.

Применение:

```bash
# через psql
psql -U postgres -d iris_restaurant -f db/triggers.sql

# через код (Node.js + pg)
npm run db:triggers

# вместе со схемой и тестовыми данными
npm run db:init
```

Скрипт идемпотентен: триггеры пересоздаются, функции обновляются, повторный запуск безопасен. [`db/schema.sql`](db/schema.sql) пересоздаёт таблицы, поэтому после его повторного применения триггеры нужно применить заново.

Проверка:

```sql
-- сумма заказа пересчитывается автоматически
INSERT INTO order_items (order_id, dish_id, quantity, unit_price)
VALUES (1, 4, 2, 520.00);
SELECT total FROM orders WHERE order_id = 1;

-- после оплаты стол освобождается
UPDATE orders SET status = 'оплачен' WHERE order_id = 1;
SELECT status FROM restaurant_tables WHERE table_id = 1;
```

## Ручная инициализация БД

Если автоматический скрипт недоступен, можно использовать `psql`:

```bash
createdb -U postgres iris_restaurant
psql -U postgres -d iris_restaurant -f db/schema.sql
psql -U postgres -d iris_restaurant -f db/seed.sql
psql -U postgres -d iris_restaurant -f db/triggers.sql
```

Важно: [`db/schema.sql`](db/schema.sql) и [`db/seed.sql`](db/seed.sql) **не создают саму базу данных** — они работают внутри уже существующей БД `iris_restaurant`. Базу создаёт либо `npm run db:init`, либо команда `createdb`.

## Проверочные сценарии

1. Войти как `guest`, открыть меню, отфильтровать роллы, забронировать стол на свободное время.
2. Попробовать забронировать тот же стол на то же время — сервер вернёт `409`.
3. Войти как `waiter`, открыть «Оформление заказа», выбрать свободный стол и обслуживавшего официанта, добавить блюда и создать заказ.
4. Убедиться, что сумма рассчитана сервером, а стол перешёл в статус «занят».
5. Войти как `admin` и провести заказ по статусам: `готовится -> подан -> оплачен -> закрыт`.
6. Проверить, что после оплаты или отмены стол освобождается.
7. Открыть вкладку «Брони», подтвердить или отменить бронь.
8. Выйти из аккаунта гостя и попробовать открыть `/api/orders` — должен вернуться `403`.

## Решение проблем

### Ошибка `password authentication failed for user "postgres"`

Укажите правильный пароль в `.env`:

```env
DB_PASSWORD=ваш_пароль
```

Затем повторите:

```bash
npm run db:init
```

### Ошибка `could not create extension pgcrypto`

Расширение `pgcrypto` создаётся от имени пользователя PostgreSQL с достаточными правами. Обычно это `postgres`. Если у пользователя нет прав, выполните один раз:

```sql
CREATE EXTENSION pgcrypto;
```

от имени суперпользователя в базе `iris_restaurant`.

### Порт 3000 занят

Измените `PORT` в `.env`, например на `3001`, и перезапустите сервер.

### Изменения в клиентском TypeScript не применяются

Клиентский код компилируется в `public/js`. После правок в папке `client` выполните:

```bash
npm run build:client
```

### Сервер пишет, что нет подключения к PostgreSQL

Проверьте:

- запущена ли служба PostgreSQL;
- совпадают ли `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` в `.env`;
- выполнена ли команда `npm run db:init`.

## Безопасность

- Все SQL-запросы параметризованы.
- Пароли хранятся в виде bcrypt-хеша `pgcrypto`, а не в открытом виде.
- Сессионная cookie имеет `HttpOnly` и `SameSite=Lax`.
- Сумма заказа рассчитывается на сервере по ценам из БД.
- Роли проверяются middleware на каждом защищённом маршруте.
- Для учебного запуска используется MemoryStore сессий. В продакшене следует подключить постоянное хранилище сессий, задать случайный `SESSION_SECRET` и работать только по HTTPS.
